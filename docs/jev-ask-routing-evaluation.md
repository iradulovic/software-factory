# Jev for Ask intent routing: no-go (evaluation v1)

2026-09-28. This evaluates the bounded decision in `OperatorQuestionParser.Parse` and `OperatorAskRouter`: a recognized Ask intent goes to the deterministic state responder; an unmatched question goes to the read-only CLI conversation. Page context validation runs before that choice. The parser also recognizes control words, but only existing code and API checks can propose and execute controls. Issue eligibility (`factory:ready`), agent labels, permissions, branch selection, and task transitions are outside this evaluation.

## Dataset and method

[`AskRoutingEvaluation.v1.json`](../tests/Factory.Api.Tests/AskRoutingEvaluation.v1.json) contains 24 redacted, self-contained prompts and a human-assigned expected intent (or `null` for conversation). H01-H09 paraphrase or reuse *examples specified* in historical issues [#124](https://github.com/iradulovic/software-factory/issues/124), [#161](https://github.com/iradulovic/software-factory/issues/161), and [#199](https://github.com/iradulovic/software-factory/issues/199); H10 comes from the existing `OperatorChatTests`. These are historical design cases, **not sampled operator traffic**. A01-A08 are synthetic semantic and contextual variants. X01-X06 are synthetic negation, quotation, and prompt-injection cases. No task IDs, repository content, issue bodies, credentials, or private data are present. The labels express the *primary user request*, not what the current parser happens to do. For example, a question about cancellation policy has `null`, even though it includes “cancel.”

Run `dotnet test tests/Factory.Api.Tests/Factory.Api.Tests.csproj --filter FullyQualifiedName~AskRoutingEvaluationTests --logger "console;verbosity=detailed"` to print every prediction and local timing. The harness uses the real production parser; it does not simulate Jev. This small, deliberately difficult set illustrates failure modes but cannot estimate production prevalence. A larger, independently labeled sample of actual consented operator prompts would be needed before rollout.

| Measure | Current parser, observed on v1 | Jev 1.13.0 |
|---|---:|---:|
| Exact intent accuracy | 12/24 (50%); historical examples 10/10, ambiguous 2/8, adversarial 0/6 | Unmeasured; no authenticated call was made |
| Conversation fallthrough | 10/24 (41.7%); six semantic status requests fell through | Unmeasured |
| False deterministic route | 6/24 (25%); all six adversarial cases | Unmeasured |
| Confidence/calibration | No probability; parser returns an intent or `null`. Calibration is inapplicable. | Unmeasured; no confidence or abstention curve |
| Local classification latency | Median 0.0041 ms, p95 0.1395 ms in one 24-case test run, including first-use regex cost | Unmeasured end-to-end. Vendor describes most queries as about 100 ms, which is not a Factory measurement. |
| Incremental classification cost | No metered API cost. Unmatched questions may invoke the existing subscription-backed CLI. | Unmeasured token use; see estimate below. |
| Failure | Parser is local and deterministic. Misroutes can produce an inappropriate control *proposal*, although existing exact-ID and eligibility guards still apply. | Timeout, 429, invalid response, service outage, and privacy/redaction failure would need explicit handling. |

Observed mistakes include A01 “Is the factory active?” falling through despite requesting running state; A05 “Which work item is first in the queue?” falling through despite asking for the next task; X01 “Do not cancel any task; explain the cancellation policy” routing to `cancel`; and X06 quoting “pause factory” routing to `pause`. No mutation occurred in this evaluation. These are also reasons a model suggestion must never confer control authority. The current route is deterministic and cheap, but the existing *deterministic-first* order means a model consulted only after a miss cannot repair false deterministic matches.

## Candidate configuration for a future offline trial

Pin model ID `jev-1.13.0`, not the moving `jev-latest` alias. Pass only a redacted `{ "question": "..." }` as state; omit conversation history, page snapshot, IDs, paths, repository text, and secrets. Use one `Choice` question: “Which single Ask intent is the user's primary request in `question`?” with criteria for `running` (current execution), `idle` (why no work), `changed` (recent activity), `attention` (work requiring the operator), `next` (next eligible task), `retry` (why a task retried), and `other` (general discussion, controls, quoted or negated control words, or unclear intent). These criteria are a proposed experimental configuration, **not a tested Jev prompt**. Never use its answer for `pause`, `resume`, `cancel`, `stop-repairs`, or `merge`.

For an offline trial, accept a read-only intent only when the returned Choice confidence is at least 0.90 and the top option exceeds the runner-up probability by at least 0.20; otherwise count it as an abstention and use the existing route. These are starting thresholds, not calibrated values. Record the returned versioned model ID, question revision, confidence, probabilities, latency, token usage, fallback reason, and ground-truth label. Split a larger labeled sample into tuning and held-out sets before changing either threshold. Compare exact intent accuracy, false deterministic routes, coverage at the threshold, reliability by confidence bin, p50/p95 latency, and cost. Require zero accepted control intents, no increase in unsafe false deterministic routes, and material improvement on the held-out read-only cases before reconsidering integration. A trial should run outside dispatch and publication; failures or low confidence should preserve the existing behavior.

## Cost and privacy

The [vendor model page](https://docs.typesafe.ai/models) lists Jev 1.13.0 at **$0.042 per million input tokens**, with output tokens free, as checked on 2026-09-28. At an assumed 300 billed input tokens per classification and 1,000 classifications/day, projected spend is 9 million tokens/month, or **$0.38/month** for 30 days. That token assumption includes question instructions and has not been measured against an API response; actual billing, volume, and pricing may differ. A direct call would also add network latency to a local route. The [vendor architecture guide](https://docs.typesafe.ai/concepts/how-to-build-with-system-one) describes most queries as about 100 ms, without a Factory-specific p95 or outage rate.

Sending even a short Ask question to a hosted provider introduces an external data recipient. User text may contain task IDs, customer names, incident details, or secrets; redaction before any call would have to be tested for both content and metadata leakage. TypeSafe [states](https://docs.typesafe.ai/models) that customer requests and responses are not used for training, and points to enterprise zero-data-retention terms; that statement does not establish a zero-retention guarantee for this installation. The vendor [documents](https://docs.typesafe.ai/model-jaggedness/jev-1.13) sensitivity to adversarial content and advises precise criteria and edge-case testing. No Factory data was sent to Jev in this evaluation. No SDK, API key, endpoint, or production dependency was added.

## Decision

**No-go for integration now.** The baseline exposes real semantic misses, but no Jev accuracy, calibration, latency, or failure measurements exist, and the current deterministic-first route would leave its unsafe false matches untouched. A hosted dependency is therefore not justified by evidence from this issue. A later, explicitly authorized offline experiment can run the pinned prompt on a larger, redacted and independently labeled set, then revisit the decision using the gates above. The current implementation remains unchanged.
